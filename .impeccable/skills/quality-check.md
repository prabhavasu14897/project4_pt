# Quality Check Skill

## Purpose

Verify that implementation matches the approved design before considering a screen complete.

---

## Visual Checklist

Check:

- [ ] Correct theme
- [ ] Correct fonts
- [ ] Correct typography
- [ ] Correct colors
- [ ] Correct spacing
- [ ] Correct borders
- [ ] Correct radius
- [ ] Correct elevation
- [ ] Correct component sizes
- [ ] Correct alignment

---

## Responsive Checklist

Check:

- [ ] Desktop
- [ ] Tablet
- [ ] Mobile
- [ ] No horizontal overflow
- [ ] No overlapping elements
- [ ] No clipped content
- [ ] Touch controls are usable

---

## Interaction Checklist

Check:

- [ ] Hover
- [ ] Focus
- [ ] Active
- [ ] Disabled
- [ ] Loading
- [ ] Error
- [ ] Empty states

---

## Accessibility Checklist

Check:

- [ ] Keyboard navigation
- [ ] Visible focus
- [ ] Semantic HTML
- [ ] Form labels
- [ ] Image alt text
- [ ] Color contrast
- [ ] Non-color status communication

---

## Code Quality

Check:

- [ ] Reusable components
- [ ] No unnecessary duplication
- [ ] No arbitrary theme colors
- [ ] No unnecessary inline styles
- [ ] No temporary placeholder UI
- [ ] No console errors
- [ ] No broken responsive behavior

---

## Final Rule

Do not mark a screen complete until both visual fidelity and functional behavior have been checked.
